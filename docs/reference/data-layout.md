# Data layout

The repo separates committed source/reference data from generated build outputs. Some workflow state is generated by the CLI but currently tracked so the repo has a useful baseline.

## Top-level directories

| Path | Purpose |
| --- | --- |
| `src/` | Production Python package. |
| `tests/` | Automated tests by feature area. |
| `docs/` | User, contributor, architecture, reference, ADR, and research docs. |
| `data/` | Input data, manual overrides, generated state, and generated artifacts. |
| `.agents/skills/` | Project-specific agent skills for safety-sensitive workflows. |
| `.github/` | CI, Copilot instructions, and GitHub templates. |

## `data/` directories

| Path | Committed? | Purpose |
| --- | --- | --- |
| `data/source/` | Usually local/source-controlled by project choice | Source Anki exports such as `All Decks.apkg`. |
| `data/manual/` | Yes | Hand-maintained overrides and curated manual data. |
| `data/reference/` | Yes for compact corpora | Reference corpora such as HSK and CEDICT; optional local extras may also live here. |
| `data/songs/lyrics/` | Yes | Curated lyric markdown files for song analysis and activation planning. |
| `data/state/` | Generated state | Workflow state such as `enriched.json` and local pipeline metadata; avoid unintended churn. |
| `data/build/` | Generated | Built decks, generated audio, test samples, and temporary build artifacts. |

Generated files under `data/build/` are ignored. `data/state/enriched.json` is generated by the CLI but currently tracked; recreate it with the CLI rather than editing it by hand, and review diffs carefully before committing changes to it. `data/state/pipeline.json` and `data/state/audio_manifest.json` are local generated run metadata and should not be committed.

## Important files

| Path | Purpose |
| --- | --- |
| `data/source/All Decks.apkg` | Default source deck export parsed by `init`. |
| `data/manual/overrides.json` | Per-character field overrides. |
| `data/manual/example_words.json` | Manual data used by enrichment. |
| `data/reference/hsk_complete.min.json` | HSK vocabulary corpus for lookup/enrichment and primary-radical grouping. |
| `data/reference/cedict_1_0_ts_utf-8_mdbg.txt` | CC-CEDICT reference data. |
| `data/state/enriched.json` | Enriched note state used by `status`, `sentences`, `audio`, and `build`. |
| `data/state/pipeline.json` | Local pipeline stage fingerprints written after successful `init`, `audio`, and `build` runs. |
| `data/state/audio_manifest.json` | Local generated-audio provenance for provider/model/voice/settings freshness checks. |
| `data/build/decks/chinese_rsh.apkg` | Final generated deck package. |

## Lyric files

Lyrics are markdown files with frontmatter:

```markdown
---
title: 学猫叫
artist: 小潘潘
---
我们一起学猫叫
```

Run this after adding or editing lyrics:

```bash
uv run anki-chinese songs verify
```

Use `--online` when you intentionally want to compare against lyrics.net.cn and are okay with network access.
